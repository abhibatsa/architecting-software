# Contributing

This repo is meant to be argued with, not just read.

## Ways to contribute

- **Add a case study** using the [template](./01-system-design-and-architecture/04-real-world-case-studies/_TEMPLATE.md)
- **Challenge a trade-off** — if you've built something similar and made a
  different call, open an issue explaining why. Disagreement with reasoning
  is genuinely useful content.
- **Fix errors** — technical inaccuracies, outdated info, broken links
- **Request a topic** — open an issue with what's missing

## How to push your contribution

If you'd like to add a new problem, improve existing content, or fix errors:

a. Fork the repository
b. Create a feature branch: git checkout -b feature/your-feature-name
c. Commit your changes: git commit -m 'Add feature changes'
d. Push to the branch: git push origin feature/your-feature-name
e. Submit a pull request

Once approved by the admin, your feature will be merged to the main/ master branch.

**Please make sure to update Readme files and documentation accordingly.**

## Style guide

- Every claim about "what breaks in production" should come from a real
  experience, not a guess — if you're not sure, say so rather than stating
  it as fact.
- Prefer real (even if rounded/approximate) numbers over vague claims like
  "high scale."
- Every case study needs a "what we'd do differently" section — that's the
  non-negotiable part of the format.
- Keep compliance/regulatory content framed as architectural guidance, not
  legal advice, and flag that it should be verified against current
  requirements in the relevant jurisdiction.
